World-Space Canvases

A UI Canvas normally draws over the screen. Set its Space to World and the same UI Document draws on a panel in the scene instead: a terminal screen, a shop sign, a wrist display. The panel is lit by nothing, sorts with other transparent geometry, is hidden by walls in front of it, and takes the mouse and gamepad like a screen canvas when the player is close enough.

Spaces

SpaceWhere the canvas draws
ScreenOver the view, scaled by ScaleMode and ReferenceHeight.
WorldOn a flat panel at the canvas object. The panel faces the object's +X axis: the object's −Y is the panel's right and −Z its down, so a panel on an object with no rotation is read by a camera looking along −X.
BillboardOn a panel at the object that always faces the camera. Its right and up follow the camera's.

Size and density

A world panel has a Size in metres and a PixelsPerMetre density. The UI Document is laid out on a canvas of Size × PixelsPerMetre pixels: the defaults, 1.0 × 0.6 m at 500 px/m, give a 500 × 300 px canvas. Anchors and Fit content work as on screen. A higher density makes the same document smaller on the panel, a lower one larger. The object's scale scales the panel.

Placing a terminal screen

  1. Add a UI Canvas component to an object in front of the terminal and assign the UI Document.
  2. Set Space to World.
  3. Set Size to the screen's size in metres, and Pixels / Metre so the canvas has the pixel size the document was designed for (a 1.6 m wide screen at 1200 px/m is 1920 px wide).
  4. Rotate the object so its +X axis points out of the screen, toward the player.
  5. Set Reach to how close the player must be to use it.

Depth

With Depth Occluded by the world, scene geometry in front of the panel hides it, as it would hide a real screen. Always on top draws the panel over everything, for markers and labels that must stay readable. Either way the panel is drawn with the scene's transparent geometry, after the opaque scene.

Input

The mouse pointer is a ray from the camera through the cursor. Where it hits the panel is the UI pixel it points at, and hover, press, drag and scroll work as on a screen canvas.

  • The panel reacts only when the hit is within Reach metres of the camera. A farther panel still draws but ignores the pointer.
  • Gamepad and keyboard navigation follow the player's gaze: they act on the panel only while the centre of the view points at it within Reach. Looking away clears the focus.

GameUi.ShowPointerRay 1 draws where the pointer ray hits each world panel, with the UI pixel, the element under it and the distance. It is a debug overlay in the game view.
